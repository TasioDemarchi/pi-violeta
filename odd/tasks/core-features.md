# core-features
Three features ported in spirit from gentle-shell into violeta, each as its own extension + tested pure modules: destructive-command guard with outside-project grants, todo list, background jobs and monitors.
Branch: main. Project: /home/tasio/Documents/violeta. No philosophy/workflow baked in; ODD is not part of violeta.

## Specs
- S1: "Lista de tareas" (from gentle-shell; user list L1).
- S2: "Guardas contra comandos destructivos y grants para repos externos" (from gentle-shell).
- S3: "jobs en backgroud y monitors" (from gentle-shell).
- S4 (guard, T1): extension `extensions/violeta-guard.ts` intercepts the `bash` tool call (pi.on("tool_call")). Recognizable destructive forms only (not a sandbox): filesystem (recursive or forced file removal, `find -delete`, `shred`, `dd` writing to devices, `mkfs`, recursive chmod/chown on broad paths; plain `>` truncation of existing files is NOT covered), git (force push, hard reset, clean with -f, checkout/restore of the whole tree, `branch -D`, `stash drop/clear`; rebase is NOT covered), database (`DROP TABLE|DATABASE`, `TRUNCATE`, `DELETE FROM` without WHERE). Wrappers (sudo, env, timeout, xargs, nohup, command, exec), separators (; && || | newline), quoted prose and heredoc data are handled so harmless text is never flagged. A match asks the user to confirm via ctx.ui.confirm showing the exact command and why; without UI it blocks. Catastrophic targets (recursive removal of `/`, `~`, `$HOME`, `/*`) are hard-denied with no prompt. Reference: gentle-pi lib/destructive-command-guard.ts (MIT; port ideas, simplify).
- S5 (grants, T1): same extension: any `read/write/edit/grep/find/ls` tool call and any bash command whose literal path arguments resolve OUTSIDE the project root (ctx.cwd) asks once per target directory per session ("Allow access outside the project: <abs path>?") via ctx.ui.confirm; the grant is in-memory only, per session, per target directory, never persisted, and lost on session change; without UI it blocks. Paths inside cwd and the violeta agent dir (`PI_CODING_AGENT_DIR`) are always allowed. `/grants` lists current grants and `/grants revoke` clears them. ASSUMPTION to report: violeta has no foreign-repo subagent launch, so "repos externos" = directories outside the project root.
- S6 (todo, T2): tool `todo` with actions write|add|update|clear|list, tasks {id,title,status(pending|in_progress|blocked|done|dropped),note}; blocked requires a note; write replaces the list keeping ids; the list is persisted in the session (custom entries) so resume restores it. Card above the editor (setWidget aboveEditor): title `Todo · N open · M done`, one row per task with glyph (○ pending, ◐ in_progress, ⏸ blocked, ✓ done, ⊘ dropped), done rows stay visible but dimmed; when more than ~8 rows, fold into `… N more`. Hidden when the list is empty or when every task has been done/dropped for more than 1 minute. `/todo` toggles the card. The hidden reminder after N tool turns is OPTIONAL: skip it.
- S7 (jobs, T3): tools `bash_background` (command, label?; returns job id immediately; when the process exits the model is woken ONCE with a custom message containing exit code and last output lines; full output saved to a temp file whose path is returned), `monitor` (command, timeout_seconds mandatory 1-1800; each output line becomes an event delivered to the model, batched within 200 ms, max 20 lines per notice; auto-stops on timeout or when it prints more than 120 lines in 60 s), `job_list`, `job_stop` (kills the process tree). Max 25 concurrent. `/jobs` opens a compact list (running first, newest first); a one-line indicator `jobs: N running` above the editor while any run. All jobs are killed on session_shutdown. Reference: gentle-pi lib/background-jobs*.ts, lib/background-monitor.ts, lib/jobs-*.ts (MIT; simplify).
- S9 (subagent titles, T6): user said "no se puede indentificar que hizo cada sub agentes si no lees todo el contexto. Me gustaria saber con el titulo que hizo cada uno" and chose "A + C". A = the Agents card shows a descriptive TITLE as the primary column (e.g. `Corregir parser de git status`), the role/agent name dimmed to its right, then tokens/cost/elapsed columns; narrow degradation drops role, then model, then tokens, then cost, then truncates the title last. C = in the `alt+a` view the left list shows glyph + title only, and the right pane shows: bold title, then `role · status · model · tokens · elapsed`, then a `── Result ──` section with the task's summary (+ up to ~6 lines of result), then a `── Thread ──` section with the full thread; while running Result shows `in progress…`. Title source: `subagent_run.label` becomes REQUIRED (description: "what this agent does, 3 to 6 words, phrased as an action"); fallback when missing/blank: first sentence of the task trimmed to 60 chars. Summary source: the `summary:` line of the result handoff if present, else the first non-empty line (cap 200 chars); failed tasks use the first line of the error. No extra model call. AgentTask gets `title` and `summary`; history files persist them; old history without them falls back to label/name.
- S10 (Spanish UI, T7): user said "veo que las preguntas las hace en ingles. Hablo español, deberia estar todo en español" (screenshot: dialog `Destructive command / Why: recursive file removal. Run it anyway? / Yes / No`). EVERY string violeta itself shows to the user is in Spanish (rioplatense-neutral, voseo not required, short and clear): confirmation dialogs (use ctx.ui.select with options ["Sí","No"] instead of ctx.ui.confirm so the options are Spanish; keep identical decision semantics: only "Sí" approves; cancel/undefined = No), notifications, /grants /todo /jobs /agents /sidebar texts and descriptions, cards (`Agentes · N activos · M terminados`, `Tareas · N abiertas · M hechas`, queued -> `en cola`, `… N más · alt+a para ver`), overlay hints (`j/k tarea  ctrl+j/k desplazar  f seguir  esc volver  q cerrar`), overlay sections (`── Resultado ──`, `── Hilo ──`, `en curso…`), sidebar sections PROYECTO / CAMBIOS / MODELO / USO with creados/modificados/eliminados, footer (`sin repo`, `limpio`, `sin modelo`), activity phases (pensando, explorando, implementando, verificando, ejecutando), jobs (`jobs: N en ejecución`, /jobs overlay), block reasons and tool-result texts that appear in the transcript. Tool NAMES, parameter names, tool/parameter DESCRIPTIONS and schemas stay English (they are for the model), as do code identifiers, comments and README. Centralize the strings in ONE module `src/i18n.ts` (grouped by area, plain functions for plurals/interpolation) so another language can be added later. Pi's own built-in strings (`Operation aborted`, dialog key hints `navigate / enter select / escape cancel`, `Working`) are Pi core and cannot be changed; report them.
- S8: every feature has tests (node --test) asserting exact outputs, plus a pty validation in a real violeta TUI; README is updated by the parent only.
