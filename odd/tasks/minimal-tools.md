# minimal-tools
Seven minimalist tools chosen by the user from a proposed list. Each is on-demand (nothing new occupies the screen by default), bilingual (src/i18n.ts es+en), and has its own extension file + pure tested modules.
Branch: feat/core-features (continue; user decides push/merge). Project: /home/tasio/Documents/violeta.
Test policy: targeted `node --test <files>` per task; ONE full-suite run by the parent at the end (T7).

## Specs
- S1 (changes viewer): `/changes` and `alt+g` open a full-terminal overlay: left = files grouped created (+, green) / updated (~, yellow) / deleted (−, red) from `git status`; right = the diff of the selected file (tracked: `git diff HEAD -- <file>`; untracked: its content with `+` lines; deleted: its removed content), colored with theme roles toolDiffAdded/toolDiffRemoved/toolDiffContext, with a one-line header `path · +A −D`. Keys: j/k (and arrows) select file, ctrl+j/ctrl+k scroll diff, g/G top/bottom, `o` opens the file in $VISUAL/$EDITOR, esc/q close. Diffs are loaded lazily on selection with a cap (e.g. 3000 lines, binary files show `binario`/`binary`), file list refreshes on open. Complements the sidebar CAMBIOS cap of 8: the sidebar summarizes, this shows everything. Not a repo => message `sin repo`/`no repo`.
- S2 (compact tool renderers): tool calls and results in the transcript collapse to ONE line by default, e.g. `✓ read README.md`, `✓ bash npm test · 0 · 1.2s`, `✗ bash … · exit 1`, `✓ edit src/a.ts +3 −1`, with a running glyph while in flight; they expand to the full call/result with Pi's existing expand control (the documented tool-output expansion toggle) and/or a violeta key; errors always show their first error line. Built from Pi's tool renderer extension points (see node_modules/@earendil-works/pi-coding-agent/examples/extensions/built-in-tool-renderer.ts and minimal-mode.ts and docs/extensions.md). Applies to Pi's built-in tools and to violeta's own tools (subagent_*, todo, bash_background, monitor, job_*). Must not hide information that is only in the expanded form from the MODEL (renderers are display-only). Theme roles only.
- S3 (notify on finish, opt-in): `/notify on|off` (no arg toggles), persisted in violeta.json key `notify` (default off). When on: when the agent settles after a run longer than 20 s, or when a confirmation dialog is waiting for the user, emit a terminal bell and, if `notify-send` exists, a desktop notification (title `violeta`, body in the active language: `Terminó: <última frase corta>` / `Finished: ...`, or `Necesita tu respuesta` / `Needs your answer`). No sound files, no extra dependencies, never throws if `notify-send` is missing. Not active for subagent children.
- S4 (quick model selector): `alt+m` and `/models` open a small overlay listing the available models (ctx.modelRegistry) as `provider/id` with the current one marked and context window; j/k + Enter switch the model for the session (pi.setModel or the documented equivalent), esc closes; footer/sidebar update immediately; notification confirms in the active language. Shows only models with auth available.
- S5 (context warning): the `ctx N%` indicator in footer and sidebar changes color at thresholds (>=70% warning role, >=90% error role) and, once per session crossing of 80%, a notification suggests `/compact` (es: `El contexto está al 80 %. Considerá /compact.` / en: `Context is at 80%. Consider /compact.`); re-arms if usage drops below 60% (after compaction). Pure threshold logic with tests.
- S6 (Claude provider): make Claude models available in violeta through the same bridge package gentle-shell already uses (`pi-claude-bridge`, declared in ~/.gentle-shell/agent/settings.json packages as `npm:pi-claude-bridge`, which relies on the user's logged-in `claude` CLI at ~/.local/bin/claude; no API key is copied, no OAuth token is extracted). Install it for violeta's OWN agent dir only (never touch ~/.gentle-shell), declared by the launcher/settings, so `violeta --list-models` shows `claude-bridge/...` models next to the 7 NaN models and one prompt works end to end with a claude-bridge model. Document what was installed and where. If the bridge needs the gentle-shell `claude-bridge.json`, replicate only harmless config in violeta's agent dir. Report any licensing/terms concern you see in the package's README.
- S7 (command palette): `alt+k` and `/palette` open an overlay with a search box listing every available command (violeta's own and Pi's, via pi.getCommands() or the documented equivalent) with its description, grouped (Session / Interface / Tools / Other), filtered as you type (substring, case-insensitive), j/k or arrows to move, Enter runs/inserts the command (if the API cannot run it directly, put `/command ` into the editor and close), esc closes. Also lists the keyboard shortcuts (alt+a agents, alt+g changes, alt+m models, alt+k palette, alt+s stop agents).
- S8: every feature has tests (es + en text where there are user-visible strings) and a real-TUI pty validation; README is updated by the parent; a final full-suite run by the parent.
